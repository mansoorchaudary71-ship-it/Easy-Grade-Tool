# Easy Grade Tool: competitive audit (6 Oct 2026)

Compared: **easygradetool.com** (your repo), **easygradecalculator.com** (call it Site A), **ezgradecalculator.com** (Site B).

## 0. What this audit is based on (and what it is not)

**Verified directly**
- Your whole repository (routes, SEO config, tool registry, sitemap, robots, headers, build scripts).
- Site A homepage and Site B homepage plus Site B's weighted-grade page, as served today.

**NOT verified. Do not treat any of this as known**

- Search volumes, keyword difficulty, backlinks, Core Web Vitals, rankings, indexation status. These need Search Console, PageSpeed Insights and a tool like Ahrefs or Semrush.
- Hidden markup on competitors (my fetch shows text, not JSON-LD blocks), so I make no claims about their schema.
- A full build. This environment has no network for `npm install`. I ran your `verify-academic-math` script (passes) and syntax-checked the one changed file.

**On "make it number one":** nobody can guarantee a ranking. Site B is an aged WordPress site with a named author, a blog, a Trustpilot profile and social accounts. Your domain declares a launch date of 2026-10-01. The code gap is small; the authority gap is mostly off-site and time-based. Section 6 lists what moves it.

## 1. Pros and cons of all three

### Site A: easygradecalculator.com
Pros
- Very focused tool: question count, custom A/B/C/D cutoffs (remembered on device), decimals toggle, print.
- Clear privacy and offline claim ("scores never leave your device").
- Clean, fast-looking single-purpose page.

Cons
- Only about 7 tools, using `.html` URLs (`gpa.html`).
- Thin copy: short how-to, formula, four FAQs. No worked-example depth, no blog.
- `twitter:card` is `summary`, no `og:image` visible. No author or ownership signal.
- Same off-niche bundle as yours (Tip, Loan, Mortgage, Password).

### Site B: ezgradecalculator.com
Pros
- Strongest trust signals: named author with social profiles, About and Contact pages, Trustpilot link, blog.
- Broad long-tail coverage: Average, Final, Weighted, GPA (college, high school, cumulative), Canvas grade calculator, grading-scale pages.
- WordPress + Rank Math + Site Kit: titles, OG images and article metadata are handled.
- Good interaction details: +/- steppers, keyboard shortcuts (Q/W/R), share chart, decimals, dark mode.
- Weighted page is genuinely strong long-form content (partial-semester denominator, "last updated" stamp, comparison table, FAQ).

Cons
- Homepage copy is generic and padded; internal anchors are mismatched (the "quick grade calculator" link goes to the weighted page, the "grading calculator" link to a Canvas page).
- AdSense present, which means ads and cookie banner friction.
- Homepage chart and some images render empty in the fetched text (heavy JS dependence).
- No custom grade-scale editor on the homepage tool that I could see.

### Your site: easygradetool.com
Pros
- Statically prerendered (SSG) for every route, so crawlers get full HTML. Consistent trailing-slash canonicals, redirect stubs, sitemap generation.
- Tool depth beats both competitors: Quick chart, weighted/points mode, final-exam solver, test grade (bonus and penalty), grade curve (4 methods), letter-grade tool, GPA, CGPA-to-% with a university table, printable/PDF chart.
- Worked examples are computed from the same math the tools use, and a math test runs in the build. This is a real accuracy and trust advantage.
- Plus/minus and custom scales, offline PWA, no ads, security-headers file, FAQPage schema that matches visible text.
- A 16-check launch audit in the build, which protects you from shipping broken SEO.

Cons
1. **Duplicate tools.** `Quick Grade` (/) and `EZ Grader` (/ez-grader/) are the same job: a questions-wrong grading chart (different components, same intent). Both were in the nav.
2. **Cannibalisation risk.** `/` and `/ez-grader/` both target "easy grader / ez grader / quick grade calculator".
3. **Off-niche tools dilute topical focus.** Tip, Loan, Mortgage, Password sit beside a grade-calculator brand (Site A does the same; Site B does not).
4. **No named owner or reviewer** (`SITE_OWNER = null` by design). Site B's biggest edge over you is trust, not tools.
5. **Fewer long-tail landing pages than Site B**: no average grade, high-school GPA, college GPA, cumulative GPA, or letter-grade-scale chart pages.
6. **No blog or guides section**, so little room to win informational queries ("how to calculate weighted grade", "what grade do I need on my final").
7. **GitHub Pages limits:** no real 301s, no response headers (your own docs say so). `public/_headers` is ignored there.
8. **Dead patch folders** are still in the repo root (`quick-grade/`, `nav/`, `seo/`, `offline/`, `docs/INTEGRATION.md`). They are listed in `DELETE.txt` but not removed. Note `DELETE.txt` also lists `public/sw.js`: check that against `vite-plugin-pwa` before deleting it, since `main.tsx` registers a generated service worker.
9. **Brand-new domain**: no links, no history, no reviews.

## 2. Your question: which overlapping tools to remove?

| Overlap you named | Verdict | Why |
|---|---|---|
| Quick Grade vs EZ Grader | **Merge (duplicate).** Done in the UI in this patch; see section 3 | Same intent, same user |
| Quick Grade vs Weighted Grade | **Keep both** | "How many wrong" chart for one test vs. a course grade built from weighted categories are different searches |
| Weighted Grade vs Final Exam | **Keep both** | "What do I need on the final" is its own high-intent query |
| Letter Grade vs GPA | **Keep both**, they are not the same | Letter grade converts one percentage to a letter; GPA averages credit-weighted letters across courses. Different inputs, different intent |
| Test Grade vs Quick Grade | **Keep, differentiate** | Points earned/possible (with bonus and penalty) vs. a wrong-answers chart |
| Tip, Loan, Mortgage, Password | **Candidate to move**, not delete | Off-topic for the brand; moving to a sub-brand protects topical authority. Not done in this patch (see section 5) |

## 3. What this patch changes (small on purpose)

`src/data/navItems.ts`: removes the duplicate **EZ Grader** tab from the header, footer tool list and nav-driven UI. Nothing else read that label (checked `src` and `scripts`). The `/ez-grader/` URL stays live and in the sitemap, so no inbound link or index entry breaks.

**Why I did not delete `/ez-grader/` or redirect it to `/`:** that route is referenced in about 20 places, including `verify-launch.ts`, `verify-selftest.ts`, `verify-worked-examples.ts`, `analyze-content.ts`, the sitemap hash file and redirect stubs. Changing it without being able to run your full build risks a failed deploy. Do it as its own change on a branch, where `npm run build` can prove it:
1. In `scripts/redirectStubs.ts` add `'/ez-grader/': '/'`.
2. Remove the route, `SELF_MANAGED` entry, sitemap entry, registry entry, and update the verify scripts.
3. Add the EZ Grader FAQ and worked example to the homepage so no content is lost.
4. Run `npm run build` and fix whatever the 16-check audit flags.

## 5. Recommended next changes (in priority order)

1. **Indexation first.** Follow `docs/SEO-OPS.md` section 0 (Search Console, sitemap, request indexing). Nothing else matters if pages are not indexed.
2. **Merge EZ Grader into the homepage** with a proper redirect (steps in section 3).
3. **Add the four missing page types** through your existing `toolPages.ts` registry, each with its own computed worked example and FAQ: average grade, college GPA, high-school GPA (weighted/unweighted), cumulative GPA. Add them one at a time so the build audit validates each.
4. **Add an Editorial/About trust layer:** a real named owner or reviewer in `siteIdentity.ts` (only if true), a corrections email (already set), a visible "last reviewed" date on each tool.
5. **Add a short guides section** (5 to 8 genuinely useful articles). Do not mass-produce AI articles.
6. **Put Cloudflare in front** for real 301s and headers (`docs/SEO-OPS.md` section 1).
7. **Move Tip/Loan/Mortgage/Password** to a sub-brand or subfolder when you have time; keep the URLs redirecting.
8. **Measure:** run PageSpeed Insights (mobile) on the 4 main pages and fix what it reports.

## 6. What actually moves rankings from here

- Backlinks from teacher-resource pages, school or university student-services pages, relevant forums (follow each community's self-promotion rules).
- Real user signals: reviews, a Trustpilot or similar profile, social accounts.
- Time: new domains typically need months.
- Keep your genuine advantages visible: no ads, accurate computed examples, custom scales, offline use.
